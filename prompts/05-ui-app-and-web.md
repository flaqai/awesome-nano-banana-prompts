# UI, App, and Web Design Prompts

## 1. Mobile app home screen

**Best for:** product discovery and stakeholder review · **Format:** 9:16 · **Difficulty:** Intermediate

```text
Create one production-minded 9:16 mobile home screen for {{app_type}} used by {{primary_user}}.
Primary job: {{user_job}}. Include a compact top bar, one status summary, one primary action,
{{count}} content cards, and a five-item bottom navigation. Use an 8-point spacing rhythm,
accessible contrast, realistic data, and {{visual_system}}. Exact screen title: "{{title}}".

No impossible controls, decorative charts, glassmorphism over text, fake device frame, brand logo,
or lorem ipsum. Keep touch targets plausible and information hierarchy clear. This is a UI concept,
not an image of a phone.
```

## 2. SaaS analytics dashboard

**Best for:** B2B concepts · **Format:** 16:9 · **Difficulty:** Advanced

```text
Create a desktop 16:9 dashboard for {{business_function}}. Layout: left navigation, top date filter,
four KPI cards, one primary trend chart, one breakdown chart, and one action table. Use only this
approved sample data: {{data}}. Highlight the decision {{decision_user_should_make}}.

Render labels and values exactly; use honest axes and consistent units. No random percentages,
meaningless charts, cropped navigation, lorem ipsum, or decorative 3D objects. High information
density with calm whitespace and accessible color semantics.
```

## 3. Landing-page hero concept

**Best for:** web design direction · **Format:** 16:9 · **Difficulty:** Intermediate

```text
Create a polished 1440-pixel-wide landing-page hero concept for {{product}}. Include navigation,
headline, supporting sentence, primary and secondary CTA, one product proof element, and an original
hero visual. Copy exactly: "{{headline}}", "{{supporting_copy}}", "{{primary_CTA}}", "{{secondary_CTA}}".
Art direction: {{direction}}. The first viewport must communicate {{single_value}}.

No fake customer logos, invented metrics, testimonials, pricing, or floating buzzword chips. Use a
clear responsive structure and leave all text legible. Do not render a browser frame.
```

## 4. Low-fidelity user-flow wireframe

**Best for:** planning before visual design · **Format:** 16:9 · **Difficulty:** Beginner

```text
Create a grayscale low-fidelity wireframe showing the {{flow_name}} flow across exactly {{screen_count}}
mobile screens. Label each screen and connect screens with directional arrows. Use standard blocks,
input fields, buttons, error states, and success state. Required steps: {{steps}}.

No color, photos, polished illustration, logos, shadows, or decorative UI. Do not skip error and empty
states. Keep labels short and arrows unambiguous. This is a product-planning diagram, not concept art.
```

## 5. Mini design-system specimen

**Best for:** visual language alignment · **Format:** 3:2 · **Difficulty:** Advanced

```text
Create a 3:2 design-system specimen for {{digital_product}}. Show color tokens, typography scale,
spacing examples, buttons in four states, form controls, tags, alert banners, one data card, and one
compact navigation component. Style attributes: {{attributes}}. Use token names and exact labels from
{{approved_tokens}}.

No invented accessibility rating, random component variants, gradients unless specified, or unreadable
microtext. Maintain consistent radii, spacing, type scale, and state semantics across all components.
```
